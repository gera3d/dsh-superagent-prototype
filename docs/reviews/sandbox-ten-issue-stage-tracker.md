## Scheduling and file ownership

- Storage-specific modules/tests, lifecycle-specific modules/tests and brief-specific domain/client modules are separate lanes.
- The fallback owner retains shared runtime files and the serialized architecture inventory until its exact-head review is sealed. Sound, brief, lifecycle, adoption and storage runtime wiring wait on that gate.
- A posted comment pending intake, or a coordinator dependency list, is not a Harness queued job. Pickup must be checked against the original input delivery/read and actual request trajectory. Idle/working labels can lag.
- Follow-up dispatch is bounded to the existing worker ceiling; pending/reserved followups count when deciding whether another task can start. Do not use a human-followup exception to exceed the requested ceiling.
